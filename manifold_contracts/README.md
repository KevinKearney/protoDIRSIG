# manifold_contracts/

Machine-readable contracts: JSON Schemas for `run-spec/1`, `sensor-spec/1`, and `dirsig-engine/1`, the governed vocabulary, test vectors, and validators. All three schemas exist, each proposed: `sensor-spec-1.schema.json` (validated in `tests/test_sensor_library.py`), `run-spec-1.schema.json` (the whole run spec: the descriptor, and the engine block selected by `descriptor.origin.engine`) and `dirsig-engine-1.schema.json` (the engine block for DIRSIG, including the proposed `new_atmosphere` and `orbit` motion forms). Each schema's `$id` is an absolute URI under `https://schemas.manifold.example/contracts/`, a base that does not resolve on the network; the run-spec schema references the other two by file name, which resolves against that base, so a validator maps the base to this folder; and the SDK API contract's `api/schemas/run_spec_document.schema.json` references the run-spec schema. `src/protodirsig/simulation.py` (`schema_errors`) remains the executable checker the SDK runs; `tests/test_run_spec_schema.py` validates every run spec the repository composes against the schemas, rejects a corpus of mutations, and holds the schemas and `schema_errors` in agreement, with each place the checker is narrower than the schema named in the test.

**What the schemas cannot express.** Admission enforces these, in the loader, not in JSON Schema: a stamped `content_hash` equals the sha256 of the referenced file, and every referenced library file exists; `settings.entry_id` names an entry of the sensor, once, and the SDK renders one entry per run; `black_level` is 0; for `motion.kind: orbit`, every task window lies inside the orbit window and the window is a whole number of waypoint spacings; a stamped hash is verified, while the placeholder `sha256:<hash>` marks a reference not yet stamped (a `.scene` ref always is) and `<git-sha>` a generator revision not yet recorded: the schemas accept both, the loader verifies neither, and a run id does not cover the bytes behind a placeholder.

`vectors/compose/<case>/` are conformance vectors for a run-spec input constructor (rules `compose/1`, CONOPS and Guide §3.5 and C-21). Each case holds layer files (`recipes/`, `scenarios/`, `engine_profiles/`) and either `expected.yaml` (the composed run spec, sensor by ref), `expected_inline.yaml` (sensor inline), or `expected_error.yaml` (`layer` and `field` the error must name). `vectors/compose/manifold_sensors/` is the cases' sensor library. `tests/test_compose.py` runs every case against `protodirsig.compose`; another constructor passes by producing the same specs and the same error locations.

The `auror_ref` and `synthetic_vis` cases are copies of the repository's own layers, and `vectors/compose/manifold_sensors/` holds copies of the library sensors they name; `tests/test_compose.py` fails when they drift. `python scripts/compose.py --refresh-vectors` rewrites those two cases (layers and `expected.yaml`) and the sensor copies from the repository; it is idempotent. The other cases are written by hand.

`vectors/identity/` holds conformance vectors for run ids and sweep ids: the RFC 8785 number and key-order vectors, and the run id of every composed document under `vectors/compose/`; its README states the definition and the invariances `tests/test_identity.py` proves. Admission enforces the three schemas (`protodirsig.contract`, through `simulation.schema_errors`).

`vectors/orbit/` is a golden vector for the propagator of a moving-platform run: a pinned TLE and the SGP4 positions (ITRS and TEME) it must give at 121 stated times, with a tolerance; its README states what a replacement propagator must reproduce. `tests/test_orbit_vector.py` runs it.

Future MANIFOLD home: the `manifold-contracts` repository, versioned by immutable git tag. Where a schema file and a field table disagree, the schema wins.
