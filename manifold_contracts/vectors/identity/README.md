# vectors/identity/

Conformance vectors for run ids and sweep ids: what another implementation of the identity rules (`protodirsig.identity`) must reproduce.

A run id is the sha256, 64 lowercase hex digits, of the RFC 8785 canonical JSON serialization (UTF-8) of the resolved run spec: the parsed `run-spec/1` document with its sensor reference `{ref: {name, content_hash}}` replaced by the referenced `sensor-spec/1` document's `sensor` block, after a stamped `content_hash` is verified. The generated file's header and the composition provenance are not part of the parsed document and are not hashed; each settings value's `provenance` label is part of it and is. A sweep id is the sha256 of the canonical JSON of the sorted list of its run ids.

`numbers.json` holds the RFC 8785 Appendix B number vectors (an IEEE-754 double as 16 hex digits and the text it must serialize to: ECMAScript `Number::toString`, `-0` as `0`, exponent form below 1e-6 and from 1e21) and a key-ordering vector whose order by UTF-16 code units differs from code-point order. `run_ids.json` holds the run id of every composed document under `vectors/compose/` (`expected.yaml`, `expected_inline.yaml` and the sweep case's `expected/*.yaml`, with `vectors/compose/manifold_sensors/` as the sensor library) and the sweep id of `sweep_three_sensors`. An implementation passes by producing the same text for every number, the same key order, and the same ids.

**Invariances** proved by `tests/test_identity.py`: the id does not change when a spec's keys are reordered, when the same values are spelled differently in YAML (quoting, `1` versus `1.0`, exponent spelling), when the same recipe is composed from a different directory (a different header), or when the sensor is given inline instead of by reference (`inline_sensor/expected.yaml` and `expected_inline.yaml` have one id). It changes when a settings value, a settings provenance label, `meta.name` or an engine value changes. A sensor reference whose stamped hash does not match the file raises instead of producing an id. Reordering a sweep recipe's sensor list keeps its sweep id; adding a sensor changes it.

A run id covers the run spec's own content and, through the materialized sensor, the sensor file's content. It covers another referenced file's bytes only through that reference's stamped `content_hash`; a `.scene` reference's stamped hash is the `dirhash/1` digest of its scene directory, so it covers the geometry and materials beside the `.scene` file; a reference that carries the `sha256:<hash>` placeholder is not covered.

`dirhash/` is the vector for `dirhash/1`, the digest a directory-valued reference (a `.scene`) carries (definition in `manifold_contracts/README.md`): `tree/` is a fixture directory of six files on two levels, one with a non-ASCII name, and `expected.json` its manifest text and digest; `tests/test_dirhash.py` checks them and the shell pipeline that reproduces the digest.
