# DIRSIG demos: layered form against pass-through

Comparisons of DIRSIG demos expressed in the layered form (CONOPS section 3.2: `engine.atmosphere.uniform`, C-39, `engine.atmosphere.simple`, C-41, `engine.platform.as_authored`, C-40, and `engine.working_folder`, C-42) with the same demo run as authored through the pass-through form. Numbers and digests only; no output byte and no demo value is in this repository.

**How.** `python scripts/compare_layered.py DensityMap1 MaterialMap1 PointCollectors2 --work <outside the repository>` (2026-10-12, DIRSIG 2026.38 (a020954), dirfm 93195ce, 36 s for all renders). Per demo the script extracts the demo's archive into a private library under `--work`, derives the layers from the demo's own files (the scene and platform by reference and hash, the `.atm` read with `basic_atmosphere.read_atm`, the one-entry `.ppd` as a static pose, the `.tasks` as epoch and windows), renders the layered recipe, the pass-through form at the same seed and the pass-through form without a seed, one at a time at the demo's native size, and compares every image both forms wrote. The derived layers hold the demo's licensed values, so they are written only under `--work` and are not committed as recipes (section 5.1); the script is the recipe's source. Seed: 1 for the layered run and the same-seed pass-through run.

**Round two (2026-10-12, same DIRSIG and dirfm).** `python scripts/compare_layered.py ColorFilterArray1 BayerPattern1 LensDistortion1 ReflectanceMap1 Telecentricity1 PolyFill1 PrimitiveObjects1 Indoors1 --work <outside the repository> --timeout 1200` (160 s for all renders): the first eight `ready` demos of the sweep report's candidate list with a deterministic reference, in its order of reference cost (`docs/DIRSIG_demo_sweep.md`, "Layered-comparison candidates"). BayerPattern1 and Telecentricity1 were rendered again by the extended script (`--work` elsewhere) for their pass-through digests; PolyFill1, PrimitiveObjects1 and Indoors1 again for the angles-only attribution, reproducing every run id and image digest of the first run.

## Known input differences

Listed for every comparison, whether or not it changed a number:

- simulation file: the layered job's jsim is written by dirfm (BasicPlatform, BasicAtmosphere, and SpiceEphemeris unless the `.atm` fixes the Sun), not the demo's own `.sim` or `.jsim`; MaterialMap1's `.atm` fixes no Sun, so its layered job names SpiceEphemeris where the `.sim` relies on DIRSIG's implicit ephemeris;

- `.atm`: written from the derived uniform or simple values; the demo's `<metadata>`, `<turbulence>` and lunar values are not carried;
- epoch's written form: dirfm writes the `.tasks` reference time in UTC, the demo with its offset; the same instant, but thermal renders differ (Balfour2, DataDrivenTempSolver1; round four; MappedTherm1, Thermal2; round six; TemperatureMap1, round eight);

- seed: the layered run states 1; the sweep's references state none (DIRSIG's default seed), so the same-seed pass-through run is the like-for-like reference;
- scene compile: dirfm runs `scene2hdf` with `--threads <cpu count>` and the seed; the pass-through runner runs it with neither (it changed a number for ChipMaker2, round eight: the image, and the truth's optical-property index numbering; and for VertexNormals2, both files, which a re-compile without the flags restores);

- working folder: DIRSIG runs a pass-through job in the demo's folder and a layered job in the job's input folder, with the scene copy in a subfolder of it and the platform at its library path; a file DIRSIG looks for in the working folder is found by the first and, unless `engine.working_folder` places it there (since round three: files a platform names, geometry lists beside the `.scene` outside its `gdbdirectory` and what they name; since round five: files a material file names in `PARAMETER_FILE`, `BRDF_FIT_FILE`, `EMISSIVITY_FILE` and `BUNDLE_FILENAME` entries relative to the scene's folder and not to its `emsdirectory`; since round seven: files it names in `EMISSIVITY_PROP` `FILENAME`, `TEMP_SOLVER` `IMAGE_FILENAME`, texture `IMAGE` `FILENAME` and `MATERIAL_MAP` `IMAGE_FILENAME` entries that the scene copy does not hold where DIRSIG looks; since round eight: `TEMP_SOLVER` `FILENAME` and `SOURCE_SHAPE` entries likewise), not by the second (BayerPattern1 and Telecentricity1 in round two; Polarization5 and BundledMaterials1 in round four; MappedTherm1 in round six);
