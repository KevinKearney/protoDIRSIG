# DIRSIG demos: layered form against pass-through

Comparisons of DIRSIG demos expressed in the layered form (CONOPS section 3.2: `engine.atmosphere.uniform`, C-39, `engine.atmosphere.simple`, C-41, `engine.platform.as_authored`, C-40, and `engine.working_folder`, C-42) with the same demo run as authored through the pass-through form. Numbers and digests only; no output byte and no demo value is in this repository.

**How.** `python scripts/compare_layered.py DensityMap1 MaterialMap1 PointCollectors2 --work <outside the repository>` (2026-10-12, DIRSIG 2026.38 (a020954), dirfm 93195ce, 36 s for all renders). Per demo the script extracts the demo's archive into a private library under `--work`, derives the layers from the demo's own files (the scene and platform by reference and hash, the `.atm` read with `basic_atmosphere.read_atm`, the one-entry `.ppd` as a static pose, the `.tasks` as epoch and windows), renders the layered recipe, the pass-through form at the same seed and the pass-through form without a seed, one at a time at the demo's native size, and compares every image both forms wrote. The derived layers hold the demo's licensed values, so they are written only under `--work` and are not committed as recipes (section 5.1); the script is the recipe's source. Seed: 1 for the layered run and the same-seed pass-through run.

**Round two (2026-10-12, same DIRSIG and dirfm).** `python scripts/compare_layered.py ColorFilterArray1 BayerPattern1 LensDistortion1 ReflectanceMap1 Telecentricity1 PolyFill1 PrimitiveObjects1 Indoors1 --work <outside the repository> --timeout 1200` (160 s for all renders): the first eight `ready` demos of the sweep report's candidate list with a deterministic reference, in its order of reference cost (`docs/DIRSIG_demo_sweep.md`, "Layered-comparison candidates"). The script was extended for them: a `.scene` origin written as `<geodeticlocation>`, a `.jsim` that names `SpiceEphemeris` without inputs (the plugin the layered job adds itself), the pass-through renders kept after a failed layered render, and a second attribution render with the demo's Euler angles alone. BayerPattern1 and Telecentricity1 were rendered again by the extended script (`--work` elsewhere) for their pass-through digests; PolyFill1, PrimitiveObjects1 and Indoors1 again for the angles-only attribution, reproducing every run id and image digest of the first run.

**Round three (2026-10-12, same DIRSIG and dirfm).** With `engine.working_folder` built (the files DIRSIG looks for in the working folder, copied into the job's input folder), `python scripts/compare_layered.py BayerPattern1 Telecentricity1 Polarization5 --work <outside the repository> --timeout 1200` (8 min 10 s, 460 s of it Polarization5's two pass-through renders): the script states the files `scene_ref.working_folder_files` finds as `engine.working_folder` (BayerPattern1 `pixels.hdf`, named by `bayer_hdf.platform`; Telecentricity1 `demo.glist`, named by `demo.scene`, and `Sphere.obj`, named by `demo.glist`; Polarization5 `pixels.dat`, named by `pi.platform`). The two layered run ids differ from round two's, because the specs now state `working_folder`; the pass-through run ids and digests are round two's.

**Round four (2026-10-12, same DIRSIG and dirfm).** The next ten `ready` demos with a deterministic reference not yet compared, in the sweep report's order of reference cost (DataDrivenArray2 among them, made `ready` by round three's `working_folder`; Thermal2, also made `ready`, has a 116 s reference and is past the cap): DataDrivenTempSolver1, BumpMap2, BundledMaterials1, DataDrivenArray2, DecalMap1, GenericMotion1, TemporalIntegration1, Balfour2, InstanceOptions1, VertexNormals1, each by `python scripts/compare_layered.py <demo> --work <outside the repository> --timeout 1200`, one at a time (15 to 46 s per demo for its renders, about 3.5 min in all; none near the 20 min drop rule). Diagnostics outside the SDK (the layered job assembled by `Simulation` with demo files swapped in, or its input folder re-rendered by `dirsig5` directly with a scratch HOME) attributed every difference; each control without a variation reproduced the layered digests.

**Round five (2026-10-12, same DIRSIG and dirfm).** With `engine.working_folder` extended to the files a material file names in `PARAMETER_FILE`, `BRDF_FIT_FILE`, `EMISSIVITY_FILE` and `BUNDLE_FILENAME` entries (relative to the scene's folder and not to its `emsdirectory`, or with an empty `emsdirectory`), `python scripts/compare_layered.py <demo> --work <outside the repository> --timeout 1200` for Polarization5 (8 min 24 s, 483 s of it its two pass-through renders) and BundledMaterials1 (14 s), one at a time. The script states the files `scene_ref.working_folder_files` finds as `engine.working_folder` (Polarization5: `pixels.dat`, named by `pi.platform`, and six files named by `chunky_bar.mat`: `materials/al-crc-015.TS.brdf`, `materials/al-crc-02.TS.brdf`, `materials/al-crc-025.TS.brdf`, `materials/al-crc-03.TS.brdf`, `materials/grass.fit`, `materials/grass.ems`; BundledMaterials1: `bundles/dirt.mat.hdf`, `bundles/glass.mat.hdf`, `bundles/subaru_red_paint.mat.hdf`, `bundles/tire.mat.hdf`, named by `w_bundles.mat`). The pass-through run ids and digests are round three's and round four's.

**Round six (2026-10-12, same DIRSIG and dirfm).** The remaining `ready` demos with a deterministic reference, cheapest first: BumpMap1, LeafStack1, MacbethColorChecker1, MappedTherm1, TriBar1, Thermal2 (the six the round named), then PrimitiveObjects2, RollingShutter1, SubObjectMotion1 and SubObjectMotion2 (the next by reference cost): 10, the cap. Each by `python scripts/compare_layered.py <demo> --work <outside the repository> --timeout 1200`, one after another (28 s to 246 s per demo for its three renders, 12.8 min in all; none near the 20 min drop rule). Diagnostics outside the SDK (the layered job assembled by `Simulation` with demo files swapped in or added, or a job's input folder re-rendered by `dirsig5` directly with a scratch HOME) attributed every difference. The last four demos' renders ran while three diagnostic renders of MappedTherm1, TriBar1 and Thermal2 also ran (two renders at once for a few minutes); all four are explained exactly (below) and their no-seed runs reproduce the sweep's digests, so the overlap changed no digest.

**Round seven (2026-10-12, same DIRSIG and dirfm).** With `engine.working_folder` extended by a fourth rule (files a material file names in an `EMISSIVITY_PROP` `FILENAME`, a `TEMP_SOLVER` `IMAGE_FILENAME`, a texture `IMAGE` `FILENAME` or a `MATERIAL_MAP` `IMAGE_FILENAME`, relative to the scene's folder, where the job's scene copy does not hold them in the `emsdirectory` or `mapdirectory`, with an image's ENVI header), `python scripts/compare_layered.py MappedTherm1 --work <outside the repository> --timeout 1200` (51 s for its three renders). The script states MappedTherm1's three files as `engine.working_folder` (`roof_metal_gray.ems`, `values.img`, `values.img.hdr`, named by `map_therm.mat`). Where DIRSIG looks was measured first, by dry runs of the layered job's input folder with the files placed in turn (scene2hdf raises the error): `values.img` is found in the working folder or the scene copy's `mapdirectory` (`auror_ref/maps`), not in the scene copy's own folder, and needs `values.img.hdr` or `values.hdr` beside it; `roof_metal_gray.ems` is found in the working folder or the scene copy's folder (the `emsdirectory`, `$SCENE_DIR`). The same rule, by the same search lists, places ChipMaker2's `materials/*.ems` (`EMISSIVITY_PROP` `FILENAME`s), `maps/texture.png` (a texture `IMAGE` `FILENAME`) and `maps/material.png` (a `MATERIAL_MAP` `IMAGE_FILENAME`): its layered dry run, which stopped on each in turn, passes with them (not rendered). The pass-through run ids and digests are round six's.

**Round seven, the demos the survey moved without a render (2026-10-12, same DIRSIG and dirfm).** Rounds twenty-five and twenty-six's survey rules moved Polarization2 (`ready`), Polarization4 (`near`), Fireball1 and EarthClouds1 (`far`) without a render; each by `python scripts/compare_layered.py <demo> --work <outside the repository> --timeout 1200`, one at a time (Polarization4 581 s, 576 s of it its two pass-through renders; Fireball1 16 s; Polarization2 46 s). EarthClouds1 was not rendered: its simulation file (`demo_basic.jsim`, the sweep's) names `FastClouds` and `OrthoImage`, plugins the layered form does not write, so the script cannot derive its layers. Polarization2 has no pass-through reference (its sweep run failed in DIRSIG) and so no identical repeat; it was rendered for the layered job's behaviour only, not compared. Diagnostics outside the SDK (Polarization4's layered job run by `Simulation.run`, which does not apply the dry-run log check, then its input folder re-rendered by `dirsig5` with a scratch HOME) attributed its difference; a control without a variation reproduced the layered digests.

## Known input differences

Listed for every comparison, whether or not it changed a number:

- simulation file: the layered job's jsim is written by dirfm (BasicPlatform, BasicAtmosphere, and SpiceEphemeris unless the `.atm` fixes the Sun), not the demo's own `.sim` or `.jsim`; MaterialMap1's `.atm` fixes no Sun, so its layered job names SpiceEphemeris where the `.sim` relies on DIRSIG's implicit ephemeris;
- motion and tasks: regenerated by dirfm from the derived values (the `.ppd` with positions to three and Euler angles to six decimals, the `.tasks` with the epoch in UTC);
- `.atm`: written from the derived uniform or simple values; the demo's `<metadata>`, `<turbulence>` and lunar values are not carried;
- epoch's written form: dirfm writes the `.tasks` reference time in UTC, the demo with its offset; the same instant, but thermal renders differ (Balfour2, DataDrivenTempSolver1; round four; MappedTherm1, Thermal2; round six);

- seed: the layered run states 1; the sweep's references state none (DIRSIG's default seed), so the same-seed pass-through run is the like-for-like reference;
- scene compile: dirfm runs `scene2hdf` with `--threads <cpu count>` and the seed; the pass-through runner runs it with neither;
- cache: the layered job runs with the user's HOME; the pass-through run with a per-run HOME;
- working folder: DIRSIG runs a pass-through job in the demo's folder and a layered job in the job's input folder, with the scene copy in a subfolder of it and the platform at its library path; a file DIRSIG looks for in the working folder is found by the first and, unless `engine.working_folder` places it there (since round three: files a platform names, geometry lists beside the `.scene` outside its `gdbdirectory` and what they name; since round five: files a material file names in `PARAMETER_FILE`, `BRDF_FIT_FILE`, `EMISSIVITY_FILE` and `BUNDLE_FILENAME` entries relative to the scene's folder and not to its `emsdirectory`; since round seven: files it names in `EMISSIVITY_PROP` `FILENAME`, `TEMP_SOLVER` `IMAGE_FILENAME`, texture `IMAGE` `FILENAME` and `MATERIAL_MAP` `IMAGE_FILENAME` entries that the scene copy does not hold where DIRSIG looks), not by the second (BayerPattern1 and Telecentricity1 in round two; Polarization5 and BundledMaterials1 in round four; MappedTherm1 in round six);
- descriptor: the layered run's sensor-spec is a library stand-in, checked but not applied (the platform is used as authored), and its collection states the scene origin and the pose's height.
